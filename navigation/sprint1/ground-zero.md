### Tools & Development Environment

| T04 | Portfolio / GitHub Pages | 3 | — | — |

**Summary:**
When my portfolio site wasn't building correctly, I kept troubleshooting over several sessions instead of giving up, eventually tracing the issue back to a misconfigured `_config.yml`. I could be more organized about documenting my troubleshooting steps as I go, rather than reconstructing what I did after the fact.

---

### Next Sprint Commitment

**One professional behavior I will improve:**

> Ask for help sooner when I'm stuck instead of spending too long troubleshooting alone.

**One technical skill I will improve:**

> Get more comfortable with the team GitHub workflow — branching, pull requests, and resolving merge conflicts.

**One way I will contribute more effectively to my team:**

> Share the troubleshooting notes I've built up so teammates don't hit the same setup issues I did.

**Evidence I will collect during the next sprint:**

> Screenshots of resolved GitHub Actions errors, commit history showing incremental progress, and notes from team stand-ups.

---

### Retrospective Questions

**What can I do now as a developer that I could not do at the beginning of this sprint?**

> I can independently set up, troubleshoot, and publish a GitHub Pages site, and I understand how VS Code, Git, and GitHub Actions connect in a real workflow.

**What did I learn about myself as a developer and teammate that I could not have learned from a grade alone?**

> I learned that I default to troubleshooting alone for too long before asking for help — recognizing that pattern is something a grade wouldn't have shown me.
